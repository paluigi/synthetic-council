Builds on the synced codebase: the simulation engine (`src/synthetic_council/simulation/`), Jev-via-`ai`-package extraction, configurable generator backends and resume-safe CLI already exist and are live-verified. Confirmed decisions: alignment vs **both** simulated and real decisions; full two-arm run 2015→present; CE proposal = **verbatim anchor**; generator configurable; governors always get the EA memo (country arm adds the annex); decision-mode evidence LLM-curated; **all agent messages archived**; profiles built from Tavily + Wikipedia only (speeches excluded); latest pre-GC speech becomes a saved memo section; CE always gets a reply turn.

## Phase 1 — Monetary policy accounts pipeline (point 1)

**1a. Collector** — new `collectors/accounts.py`, registered in `scripts/collect_all.py`:
- Enumerate account records from `data/raw/foedb_publications.parquet` (title/type filter, confirmed at implementation); English `documentTypes` URL (pattern verified: `/press/accounts/{year}/html/ecb.mg{YYMMDD}~{hash}.en.html`).
- Meeting date from title/body ("…held on Wednesday and Thursday, 18-19 March 2026", decision day = day 2); validated ±35d against `gc_decisions.announcement_date`, mismatches logged.
- Fetch HTML (politeness sleep, existing `USER_AGENT`), convert to markdown (`markdownify`, new dep) preserving headings/footnotes/asterisks → `data/raw/accounts/{meeting_date}_account.md` + `data/raw/accounts_index.parquet`. New `docs/data-sources/ecb-accounts.md`.

**1b. Extraction** — new `src/synthetic_council/mpa_extract/`, parquet+csv to `data/processed/`, provenance columns (`source_span`, `method ∈ {deterministic, llm}`):
- `participants.py` (deterministic): parse the trailing Attendees section; asterisk → `voting_right` + footnote text; names canonicalised via `persons.py`; cross-checked vs `gc_memberships_wayback` (closes the voting-rights and attendance-check TODOs). Output `account_participants.parquet` (+ `is_chief_economist` via the CE tenure table). Fallback: parse attendance from raw HTML if markdown mangles asterisks.
- `decision_mode.py` (LLM-curated evidence → Jev): the chat model reads the account's §2 (chunked if needed) and extracts **verbatim** the passages characterising how the decision was reached (who supported/opposed, unanimity/consensus/majority language, "large majority" → majority flagged); a deterministic keyword harvest over §2 is the pre-filter/cross-check. Jev `ChoiceQuestion` over {unanimity, consensus, majority} with Bruegel/Trichet definitions in the criteria. Output `account_decision_mode.parquet` (evidence quotes, all three probabilities, argmax, model + prompt_version, method).
- `ce_proposal.py` (deterministic-first): closing paragraph of §1 matching `(Mr|Ms) {CE} therefore proposed…` (tenure table: Praet → 2019-05, Lane 2019-06 → present, verified against data); direction/bp parsed; LLM fallback flagged. Output `account_ce_proposal.parquet`.
- Fixture-based tests for all three.

## Phase 2 — Member profiles (Tavily per-trait + Wikipedia) + pre-meeting speech sections

**2a. Speech corpus** — `collectors/ncb_speeches.py` (new): fill the governor-speech gap from the **BIS central bankers' speeches database** (paginated listing filtered to Eurosystem institutions, per-speech pages scraped with polite delays); speaker names canonicalised via `persons.py` → `data/raw/speeches/bis_speeches.parquet`. Union with the ECB Executive-Board CSV into one corpus. Coverage limits documented. Speeches feed **only** the memo section below — not the profile.

**2b. Latest-speech join (strict window)** — per member and meeting, the latest speech **after the previous monetary policy meeting and on/before the current one** (window = `(prev_gc_date, gc_date]` from `gc_decisions`; replaces the current 120-day rule). Output `latest_speech_per_meeting.parquet` (person, meeting_date, speech_date, title, source, text ref).

**2c. Speech-stance memo sections (saved, reusable)** — `member_profiles/speech_sections.py`: for each (member, meeting) with a qualifying speech, one LLM call extracts the policy stance into a short section — "In your most recent speech ('title', date) you advocated …" — saved to `data/processed/speech_sections/{meeting_date}_{person}.md` + parquet index (person, meeting_date, speech ref, model, prompt_version). Each speech qualifies for at most one meeting, so sections are stable and reusable. **No qualifying speech → the section is omitted from that memo.**

**2d–2f. Profile building — single script, one reviewable file per member** — new `scripts/build_profiles.py` (single entry point, also runnable as `python -m synthetic_council.member_profiles`) that runs the whole profile pipeline for every GC member and writes **one dedicated markdown per member** to `data/processed/member_profiles/{Person}.md` for your manual review. Steps inside:
- **Tavily per-trait evidence** — simple, single-purpose queries, one per **stable, time-invariant trait** (the profile is built once per member, not per meeting — no era- or meeting-specific questions like dissents or negative-rate views). Default trait set (query templates in `config.py`, editable):
  - "{name} {role} monetary policy stance hawkish or dovish"
  - "{name} economist career background"
  - "{name} economic thinking and intellectual formation"
  - "{name} approach to the ECB price stability mandate"
  Each call (Tavily search API, `include_answer`, advanced depth; `TAVILY_API_KEY` in `.env.local`) saves the **raw answer + sources** to `data/raw/profiles/tavily/{person_slug}/{trait}.json`; cached/resumable; failures logged and skipped.
- **Wikipedia evidence** — search → best page match (disambiguation with role context), plaintext extract saved raw → `data/raw/profiles/wikipedia/{person_slug}.json`.
- **Synthesis** — merge deterministic fields (roles/tenures/country from repo data) + per-trait Tavily answers + Wikipedia extract into the member's markdown: one section per trait with per-section source tags. Missing streams degrade gracefully (trait omitted, flagged). Identical across both experiment arms.
- **Review-safe re-runs**: by default the script does not overwrite an existing profile file (your manual edits are preserved); `--rebuild` regenerates, `--only "Name"` rebuilds one member; prints a review index (member → file → missing traits).

`memo.py`: memo gains the compact profile section + the 2c speech-stance section (when present); the old last-speech-excerpt section is replaced.

## Phase 3 — Simulation restructure (points 2–3) + message archive

Modifications in `src/synthetic_council/simulation/`:
- `config.py`: `arm`, decision-mode thresholds, accounts/profiles paths.
- `agent.py`: `Agent` gains `is_chief_economist`, `voting_right` (roster = `account_participants` ∩ memos; memo-only fallback for pre-2015, warned). Round-1 prompt rewritten to respond to the CE's proposal; persona enriched by the Phase-2 profile. Speaking order stays deterministic (alphabetical, as today).
- `discussion.py` — fixed flow, no config switches:
  1. **CE proposal** injected verbatim (no LLM call);
  2. **round 1** — the other agents react (memo-grounded positions relative to the proposal);
  3. **round 2** — the other agents respond to colleagues;
  4. **CE reply** — the CE (LLM, in character) always gets a turn to reply to the discussion, defending or adjusting the proposal;
  5. **final summary positions** — every member states a position relative to the proposal (existing final-statement step, prompt updated).
  Pre-discussion Jev extraction anchors on round-1 statements → existing before/after delta analysis preserved.
- `decision.py` (new): President (LLM) formulates the decision statement; deterministic cross-check = modal stance of voting-right members; both recorded.
- `alignment.py` (new): per agent, parallel Jev `ChoiceQuestion` {aligned, non_aligned} against two references — the simulated decision and the real decision → `p_aligned_sim`, `p_aligned_real` + full distributions.
- `mode.py` (new): simulated decision mode both ways — Jev on the simulated closing section with the *same criteria as Phase 1b*; deterministic aggregation of `p_aligned_sim` (config thresholds). Both saved.
- `recorder.py` (new): every generator and Jev request/response logged — system prompt, user prompt, response, agent, round, stage, model, token usage, timestamp — to `messages.jsonl` per meeting; human-readable `transcript.md` (proposal → rounds → CE reply → final statements → decision, in order). Archived alongside the payload JSON so future experiments can reuse messages without re-running.
- `runner.py` + `scripts/run_simulation.py`: orchestrate the new steps; payload extended (arm, ce_proposal, decision, alignment, mode); CLI gains `--arm ea_only|country` with outputs under `data/processed/simulations_{arm}/`; resume unchanged.
- Tests: extend the faked-backend pattern (fake generator + fake Jev + fake recorder) covering proposal injection, CE turn structure, decision, alignment, mode, arm routing, archive completeness.

## Risks & mitigations

- **Web-evidence quality** (Tavily answers can be wrong; Wikipedia coverage uneven) → raw answers + sources archived verbatim; per-trait provenance; one-file-per-member review workflow lets you correct cards manually, and re-runs preserve edits.
- **BIS governor-speech coverage is selective** → documented; strict inter-meeting window means many meetings legitimately have no speech section (omitted, as specified).
- **LLM-curated decision-mode evidence could hallucinate** → verbatim quotes stored and checkable against the archived account markdown; deterministic keyword cross-check; prompt/model versions recorded.
- **Asterisk survival in HTML→markdown** → fixture verification, raw-HTML fallback.
- **Pre-2015 meetings** lack accounts → anchored evaluation is 2015+; memo-only roster fallback available explicitly.
- **Cost/robustness** → resume, retries; message archive + saved speech sections + saved profiles enable partial re-analysis without re-running LLMs.
