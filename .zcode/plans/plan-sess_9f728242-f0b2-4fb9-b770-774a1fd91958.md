TinyFish press layer — fill post-2023 speech gaps with news coverage
=====================================================================

Confirmed: press only fills gaps (never displaces a real speech in the
strict window); search covers every participating member of 2024+
meetings without a speech in the window. Key `TINYFISH_API_KEY` is
already in `.env.local` (verified). Key handling stays trivial:
`os.environ.get("TINYFISH_API_KEY")`, exported before running
(`set -a; source .env.local; set +a`) — same as the other LLM-dependent
modules. No loader machinery.

1. New collector `src/synthetic_council/collectors/press_speeches.py`
   - `search(query, after_date, before_date, domain_type="news")` → GET
     api.search.tinyfish.ai; `fetch(url)` → POST api.fetch.tinyfish.ai.
     Both take the key from the environment; raw search JSON archived per
     query under `data/raw/speeches/press_searches/`.
   - Windows `(prev_gc, gc]` from `gc_decisions.parquet`, 2024-01-01 →;
     roster via `speech_union._roster`; a member needs a search only when
     the existing union corpus has no speech for them in the window.
   - Per (person, window): 1–2 queries; results hard-clipped to the window
     by publisher date (undated dropped); subject check via the
     cbs_speeches resolver (name in title/head + tenure); fetch top 6,
     keep ≤2 articles ≥600 chars.
   - Output `data/raw/speeches/press_speeches.parquet` (corpus schema +
     source='press', publisher); dedup on (speaker, date, url); collisions
     with existing sources on (speaker, date) dropped. Resume index
     `press_fetched.parquet`, flush-every-100 (ncb_websites pattern).
   - search/fetch are plain injectable function parameters — tests pass
     fakes directly, no monkeypatching.

2. `speech_union.py` — press as fallback only: latest non-press speech per
   speaker in-window; press only for speakers with none.

3. `member_profiles/speech_sections.py` — press-framed prompt for
   source=='press' rows (positions attributed in quoted remarks + analyst
   framing; section text states it is press coverage, not a verbatim
   speech); prompt version `ss-press-v1`. Memo template unchanged.

4. Wiring + docs: `.env.example` gains TINYFISH_API_KEY; `collect_all.py`
   gains the press step (only when the key is set);
   `docs/data-sources/press-tinyfish.md`, TODO/README updates.

5. Tests (offline, fakes passed as parameters): window clipping incl.
   undated-drop; subject filter; dedup vs existing; resume index; union
   fallback semantics (real speech never displaced); press prompt chosen
   for press rows.

6. LIVE VALIDATION (staged)
   a. Smoke: one real Search + one Fetch (Knot, one 2024 window); print
      raw response fields to pin the actual JSON schema before parsers
      are finalised.
   b. Pilot: one meeting window end-to-end (e.g. 2024-04-11 → 2024-06-06);
      inspect kept rows and one generated press section; adjust
      prompts/filters if quality is off.
   c. Full run: all 2024+ windows; rebuild speech_union → speech_sections
      → memos; report the join delta (new member-meeting links by
      country — expect PT/LU/one-offs to fill).

7. Close-out: pytest + ruff clean; commit; push to the feature branch.

Out of scope: pre-2024 windows, TinyFish Agent/Browser (paid), changes to
the simulation engine.
